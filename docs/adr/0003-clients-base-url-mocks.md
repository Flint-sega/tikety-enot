# 0003. Внешние клиенты принимают base_url, приёмка интеграций — на моках

## Контекст

Панель обязана работать и тестироваться полностью без токенов UseDesk и Telegram: токены появляются у владельца позже и вписываются вручную. Прогоны тестов не должны трогать рабочие аккаунты.

## Решение

Клиенты UseDesk и Telegram построены на httpx и принимают base_url параметром; в тестах транспорт подменяется записанными ответами внешних API (httpx.MockTransport). Живые токены проверяются только вручную — чек-листом владельца и тест-кнопками в админке.

## Почему

- Тесты против живых API отвергнуты: каждый прогон создавал бы настоящие тикеты и сообщения в рабочем UseDesk и телеграм-группе, плюс зависимость от сети и чужих лимитов.
- Песочница UseDesk отвергнута: опубликованного тестового контура не существует; единственная опора — спайк официальной документации с зафиксированными форматами ответов.
- Подмена клиента целиком заглушкой отвергнута: тест перестаёт видеть, что реальный код клиента собирает неверный запрос; подменяется транспорт, а сам контракт остаётся под тестом.

## Последствия

- base_url — публичная сигнатура шва из interfaces.md: поменять её — сломать все тесты и все вызовы разом, только через правку файла швов.
- Моки — слепок со спайка, а не с истины: расхождение живого API с записью проявится лишь на ручной проверке, поэтому спайк и моки обязаны меняться вместе.
- Зелёные тесты не доказывают работающую интеграцию; доказывает только прогон владельца с настоящими токенами — это надо держать в чек-листе переноса.
