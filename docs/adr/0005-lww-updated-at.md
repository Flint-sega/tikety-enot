# 0005. Конфликт статусов — LWW по updated_at с пином часов

## Контекст

Статус одной заявки могут менять независимо с двух сторон — оператор в панели и агент в UseDesk, с зазором до минуты между циклами синка. Синхронизируются только создание и статус; нужен детерминированный победитель конфликта без двусторонних подтверждений.

## Решение

При конфликте статусов побеждает более поздняя правка: сравнение по updated_at заявки, last-write-wins. Поллер, записывая служебные поля синка, пинит updated_at — служебная запись не двигает часы и не искажает следующий арбитраж.

## Почему

- «UseDesk всегда прав» отвергнуто: закрытие, сделанное оператором, пока UseDesk был недоступен, откатывалось бы задним числом без всякого уведомления.
- «Панель всегда права» отвергнуто симметрично: действия агентов в UseDesk (ответ клиенту, спам, переоткрытие) никогда не доходили бы до панели, и синк вырождался в односторонний.
- Хранение обеих версий со слиянием отвергнуто: статус бинарный, «объединённого» значения показать некуда, а векторные часы несоразмерны одному полю.

## Последствия

- Часы локальные: сбитое время машины искажает арбитраж; единственная защита — дисциплина пина при любой записи в заявки.
- updated_at перестаёт быть «просто временем последней правки»: любой новый код, пишущий в заявки, обязан знать о пине, иначе молча сломает разрешение конфликтов.
- Редкий одновременный разнонаправленный перевод статуса завершается проигрышем одного из действий, и проигравшая сторона уведомления не получает.
