# 0002. Входящий синк — поллинг UseDesk, не вебхуки

## Контекст

Панель должна узнавать о чужих действиях в UseDesk (ответ агента, смена статуса) без ручного переноса. Панель слушает только локальный интерфейс и публичного адреса по замыслу не имеет.

## Решение

Входящие изменения забираются фоновым поллером с циклом 60 секунд: запрос к UseDesk «что изменилось с отметки watermark» и обновление локальных заявок. Вебхуки не используются.

## Почему

- Вебхуки отвергнуты: UseDesk должен дотянуться до панели, а панель за localhost — это публичное развёртывание, TLS и входящая аутентификация, то есть смена всей модели развёртывания ради одной интеграции. Возврат к вебхукам возможен только вместе с будущим публичным переносом.
- Поллинг по действию пользователя (кнопка «обновить») отвергнут: агент в UseDesk про панель не знает, ручной обмен уничтожает смысл двусторонности.
- Цикл короче минуты отвергнут: лимиты запросов UseDesk документацией не опубликованы, а выигрыш в свежести данных характер работы не меняет.

## Последствия

- Изменение в UseDesk доезжает до панели до минуты спустя — это норма, о которой владелец должен знать, а не дефект.
- В зазоре между циклами обе стороны могут менять одну заявку независимо — отсюда отдельное решение об арбитраже конфликтов (ADR 0005).
- Поллер — постоянно живущий фоновый цикл, который спит при выключенном тумблере: его молчание неотличимо от смерти без диагностических кнопок в админке.
