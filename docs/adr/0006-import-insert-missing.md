# 0006. Импорт заявок из JSON — insert-missing по id

## Контекст

Панель загружает заявки из внешнего JSON-файла (seed) при первом старте и по команде. Файл могут дополнять и загружать повторно, когда панель уже работает и в ней появляются собственные заявки. В таких файлах встречаются неполные записи — закрытые без даты закрытия и заявки без даты создания.

## Решение

Импорт добавляет только заявки с отсутствующими id; существующие записи не перезаписывает никогда, повторный прогон ничего не добавляет. Загруженные заявки сохраняют исходные id (в `legacy_id`) и номера. Сбой импорта не мешает старту панели.

## Почему

- Полная замена содержимого при каждом импорте отвергнута: стёрла бы заявки, уже созданные в панели.
- Выдача новых id при загрузке отвергнута: повторный прогон создавал бы полные дубли, а сверка «что уже загружено» превратилась бы в отдельную задачу без естественного ключа.
- Дочинивание неполных записей при импорте (выдумывание дат) отвергнуто: это фальсификация истории заявок; пропуски честно отображаются прочерком.

## Последствия

- Правки уже загруженных записей в файле до панели не доезжают: добавляется только то, чего ещё нет.
- Порядок «импорт до первой созданной заявки» желателен из-за сохранения номеров; иначе совпавший номер даёт конфликт, который импорт пропускает с записью в журнал.
- Даты неполных записей остаются пустыми навсегда; «починить» их можно только правкой файла и повторным прогоном по чистой базе.
