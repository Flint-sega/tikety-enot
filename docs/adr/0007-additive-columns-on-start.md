# 0007. Новые колонки дописываются при старте, без Alembic

## Контекст

ADR-0001 отложил инструмент миграций «до первого изменения полей». Волна 4 (20.10.2026) — шаблоны заявок от операторов — впервые требует новых полей в существующей таблице: автор шаблона и признак «для всех» (`templates.created_by`, `templates.is_shared`). `create_all` создаёт только отсутствующие таблицы, в рабочую БД колонки сам не добавит.

## Решение

`app/db.init_db` после `create_all` сверяет таблицы со списком `ADDITIVE_COLUMNS` и выполняет `ALTER TABLE … ADD COLUMN` для недостающих. Разрешено только добавление колонок со значением по умолчанию (NULL или константа), без переименований, удалений и переноса данных. Старые шаблоны получают `is_shared = 1` (общие, как и были) и `created_by = NULL` (правит только админ).

## Почему

- Alembic по-прежнему дороже задачи: две колонки, один владелец схемы, одна БД на инсталляцию.
- Разовый ручной скрипт отвергнут: его легко забыть при обновлении, а установка «одной командой» должна обновлять схему сама.
- `ADD COLUMN` с DEFAULT в SQLite атомарен и не переписывает таблицу; повторный старт ничего не делает (идемпотентно).

## Последствия

- Любое изменение схемы сложнее «добавить колонку» (переименование, смена типа, перенос данных) по-прежнему требует решения: Alembic или отдельный ADR.
- Список `ADDITIVE_COLUMNS` — часть схемы: новая колонка в моделях существующей таблицы без строки в этом списке сломает старые БД.
